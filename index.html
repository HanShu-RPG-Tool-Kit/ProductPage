Overview

一个工程，两端，同一份内容 One project. Two ends. One source of truth.

编辑器负责“写下来”，引擎负责“跑起来”。它们通过自有文件格式与工程协作服务对接，从剧本到游戏里的一帧画面，中间不需要导出脚本、手改 JSON。 The IDE writes it down; the engine runs it. They meet through a set of project formats and the collaboration service — no hand-written JSON, no export scripts between script and scene.

编辑端直接连游戏The editor talks to the game

Web 端不直接读游戏，而是通过 Devtool Server / Control 通道联调：热重载内容、看游戏内效果、抓运行时诊断，都在同一条链路上。 The web editor never touches the game directly — it talks through the Devtool Server and Control channel: hot-reload content, inspect in-game results and capture runtime diagnostics on one link.

  • Devtool Server：本机控制面 WebSocket 与帧串流: local control WebSocket and frame streaming
  • PAK 发版协议：编译产物按 client / server / shared 分包 release protocol: compiled output split into client / server / shared
  • IBE 编辑器与受限 Python 插件宿主（宿主 API 2.0.0） editor with a restricted Python plugin host (host API 2.0.0)

Collaboration · Formats

团队一起写，版本说了算 Team editing, versioned by default

所有资源接入同一个工程服务：同一份历史、同一套权限。每笔有效事务立即归档，可命名版本、比较文件、恢复单资源或整个工程。 Every resource rides the same project service: one history, one permission model. Each valid transaction is archived at once — name versions, diff files, restore a resource or the whole project.

局域网协作LAN collaboration

本机开启共享，复制地址即可邀请；密钥留在宿主，浏览器只拿短期会话，刷新需重登。

Share from the host and hand out a link; the key stays on the host, browsers hold only short sessions and must log in again after refresh.

命名版本与比较Named versions & diffs

按编辑时段聚合历史，比较文件差异；恢复也走权限与版本校验并生成新版本。

History aggregates by editing session; compare files. Restoring also passes permission and version checks, then creates a new version.

安全边界Security by design

密码以 Argon2id 哈希存于服务端；内置 Admin 只能由本机宿主建立会话，远端不可登录、无注册入口。

Passwords are Argon2id-hashed server-side; the built-in Admin session can only be created by the local host — no remote login, no sign-up.

FAQ

常见问题Questions

编辑器需要联网吗？Does the editor need internet?
不需要。本机宿主会同时保管工程目录与协作服务，打开本机工程即可离线创作；共享只走局域网 HTTP，目前不提供公网穿透。No. Your machine hosts both the project directory and the collaboration server, so you can work offline. Sharing runs over LAN HTTP only — there is no public tunnelling yet.
两个人同时改同一个任务会怎样？What if two people edit the same quest?
服务端会校验被修改字段的原值并短暂取得写权。不同字段可以并行修改；同一字段冲突时会保留你的输入并明确提示，撤销/重做只回滚你自己引用的操作回执。The server verifies the original values of the fields being changed and briefly takes a write lock. Different fields edit in parallel; a same-field conflict keeps your input and tells you clearly, and undo/redo only references your own receipts.
支持哪些 Minecraft 版本？Which Minecraft versions?
当前基线为 Minecraft 26.1.2 + NeoForge 26.1.2.109 + Java 25。版本绑定较紧，因为服务端与客户端都需要同时支持内容运行时与 Devtool 通道。Current baseline: Minecraft 26.1.2, NeoForge 26.1.2.109, Java 25. The version is tightly pinned because both sides must support the content runtime and the Devtool channel.
只做剧情剧本、不装模组可以吗？Can I only write scripts, without the mod?
可以。编辑与工程历史完全独立于游戏运行；但要让对白、任务、演出在游戏里生效，需要安装 HanShu RPG Tool Kit 并加载导出的 PAK。Yes. Authoring and project history work independently of the game. To make dialogue, quests and staging take effect, install HanShu RPG Tool Kit and load the exported PAK.
可以商用吗？Can I use it commercially?
WebUI 采用 MIT；模组采用 BUSL 1.1——每个版本发布满两年自动转 MIT，未满两年允许复制、修改、分发与非生产使用，商业用途受限。“HanShu”作为项目组合名与商标不随 BUSL 到期开放。WebUI is MIT; the mod is BUSL 1.1 — each release becomes MIT two years after publication. Before that, copying, modifying, distributing and non-production use are allowed; commercial use is restricted. The “HanShu” name and trademark do not open up when BUSL expires.
我可以写插件吗？Can I write plugins?
可以。IBE 编辑器提供受限的 Python 插件宿主（宿主 API 2.0.0），支持 manifest、能力审批、目录导入、签名 HTTPS 目录、包哈希校验与更新回退。官方随仓库提供了 Curios 饰品编辑器示例。Yes. The IBE editor offers a restricted Python plugin host (host API 2.0.0) with manifests, capability approval, directory import, signed HTTPS registries, hash verification and update/rollback. An official Curios trinket editor example ships with the repo.
